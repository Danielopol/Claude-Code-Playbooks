## What This Does

Helps you design and implement a tracking plan grounded in business decisions — choosing the right events, naming them consistently, configuring GA4 and GTM, validating the implementation, and setting up UTM conventions that survive contact with reality.

## Inputs You'll Need

- **Business context** — what decisions will this data inform; what are the key conversions
- **Current state** — what tracking exists, what tools are in use
- **Tech stack** — site/app platform, dev resources, privacy/compliance requirements
- **Tools** — GA4, Mixpanel, Amplitude, PostHog, Segment

## How It Works

1. Start with the questions you need answered, then work backwards to events
2. Apply object-action naming conventions (`signup_completed`, `cta_clicked`)
3. Define essential events for marketing site and product/app, with standard properties
4. Configure GA4 (property, data stream, enhanced measurement, custom events, conversions)
5. Set up GTM container with tags, triggers, variables, and a clean data layer
6. Define UTM conventions and document them in a single source of truth
7. Validate with DebugView, GTM Preview Mode, and a tag-firing checklist

## What You Get

- Tracking plan document with event names, descriptions, properties, and triggers
- GA4 implementation guide and gtag.js examples
- GTM container structure with data layer pattern
- UTM parameter strategy with naming rules
- Debugging and validation checklist
- Privacy and consent considerations (cookie consent, IP anonymization, consent mode)

## Tips & Best Practices

- **Track for decisions, not data** — every event should inform an action. Quality over quantity.
- **Be specific in event names** — `cta_hero_clicked` beats generic `button_clicked`
- **Keep context in properties, not event names** — easier to filter, easier to evolve
- **Avoid PII in analytics properties** — bake privacy in from day one
- **Validate before publishing** — DebugView and GTM Preview catch most issues in 5 minutes
