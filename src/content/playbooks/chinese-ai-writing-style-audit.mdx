## What This Does

An 11-rule checklist for auditing Chinese reader-facing copy — product announcements, WeChat/公众号 articles, emails, README sections — for the specific patterns that mark it as unedited AI output. Each rule is a precise, self-contained unit: a trigger condition (what has to repeat or combine to actually count as a violation, not just any single instance of the pattern), a detection approach, a genuine bad/good example pair, a concrete fix, and a scope stating exactly which document types it applies to.

The patterns cover ground English-language AI-writing guides don't touch: chaining em-dashes in place of normal punctuation, repeating "不是……而是……" (it's not X, it's Y) contrast pairs, stacking "让我们" rallying-cry openers, mechanically sequencing every sentence with 首先/其次/最后, vague "在这个……时代" era-framing openers, emoji density in formal copy, forced parallel structure, empty poetic metaphors standing in for real information, overloaded long sentences, repeated "值得注意的是" preambles, and chained 被-passive constructions. It was refined from real user correction feedback, not written from theory alone.

## Tips & Best Practices

- Detection here is judgment-based, not a mechanical string match — every rule's trigger depends on repetition, scope, and whether the pattern is doing real work, so read each passage in full context before flagging it.
- Respect each rule's stated scope. A rule calibrated for formal product announcements (like the emoji rule) shouldn't be applied wholesale to a casual internal chat message.
- When several rules fire in the same passage, fix the most disruptive one first — usually the em-dash chain or the overloaded sentence — since smaller issues often resolve naturally once the structural ones are fixed.

## Limitations

- Calibrated specifically for Chinese-language reader-facing copy — the patterns here are language-specific and don't transfer directly to English AI-writing detection (pair with an English-focused humanizing playbook for that).
- Every rule's "does not trigger" exception exists for a reason — don't mechanically flag every instance of a pattern without checking whether the exception applies to this specific passage.
- Refined from real correction feedback on specific document types (product posts, WeChat articles, emails, READMEs) — a genuinely different genre, like fiction or academic Chinese writing, may need different calibration.
