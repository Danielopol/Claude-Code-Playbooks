## What This Does

A static, no-guesswork audit of the structural things that quietly inflate Claude Code token cost on every turn — it doesn't call a pricing API or try to reconstruct past spend, it inspects the setup for the handful of well-known leaks and returns a fix list ranked by biggest win per unit of effort. The headline culprits it catches are the ones that compound silently: an oversized CLAUDE.md (which is prepended to literally every message, so every excess line costs tokens forever), bloated memory files that should be a linked index rather than a dump, large skills that are never invoked yet still load into the skill index each turn, and — the sneakiest one — a settings hook that injects a timestamp or random value into every turn, breaking the prompt cache in a way that can roughly 10x cost while nothing visibly fails.

Each of seven checks produces a PASS/WARN/FAIL with a concrete bash command to run and a specific remediation, and the output is a priority-ranked list so the most impactful fix surfaces first. It's deliberately honest about its own limits: it estimates *relative* impact ("~30% smaller context") and explicitly refuses to invent dollar figures unless you supply your actual bill, pointing you to a before/after cost check to validate.

## Quick Start

### Step 1: Create a Project Folder

```bash
mkdir cost-optimizer && cd cost-optimizer
```

### Step 2: Download the Template

Click **Download** above, then:
```bash
mv ~/Downloads/CLAUDE.md ./
```

### Step 3: Audit a Project

```bash
claude
```

Point Claude at the project whose costs you want to understand and ask it to audit for token waste. It will run the seven checks, score each PASS/WARN/FAIL, and return a priority-ranked fix list with the biggest win first — without inventing dollar savings.

## Tips & Best Practices

- Fix the cache-hygiene finding first if it appears — a hook that injects changing content every turn is the single highest-leverage cost leak, since prompt caching is doing most of the work of keeping a long session affordable.
- Treat CLAUDE.md as a thin pointer, not a knowledge base — anything a given task doesn't always need (runbooks, verbose examples, reference tables) belongs in a skill file or `docs/` that's loaded on demand rather than prepended to every message.
- Re-run the audit after making changes and compare with an actual before/after cost check — the tool deliberately won't fabricate savings numbers, so the real validation is measuring your own per-turn overhead drop.

## Limitations

- A static structural inspection only — it finds setup-level leaks (context size, cache hygiene, model pinning) but can't see into the actual content of a runaway conversation or diagnose a genuinely token-heavy task that legitimately needs the context it uses.
- It estimates relative impact, never absolute dollar savings, unless you provide your current bill — anyone wanting a hard currency figure has to supply the baseline themselves.
- The specific thresholds (100/300 lines for CLAUDE.md, 500/1500 for memory) and file paths assume a conventional Claude Code project layout; adapt them if your setup stores these files elsewhere.
