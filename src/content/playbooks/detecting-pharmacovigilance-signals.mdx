## What This Does

A working, statistically grounded guide to disproportionality signal detection — the core technique pharmacovigilance uses to screen spontaneous adverse-event reports (like the FDA's FAERS) for drug-reaction pairs that occur together more often than the background rate would predict. It builds the underlying 2x2 contingency table directly from live queries against the free, public OpenFDA `/drug/event` API (no PHI involved, no MedDRA license needed to query already-coded terms), then computes PRR, ROR with a Woolf's-method confidence interval, and the Information Component (IC/BCPNN) from working Python — with Empirical Bayes EBGM/EB05 correctly deferred to a maintained statistical package rather than hand-rolled, since the gamma-Poisson shrinkage math is easy to get subtly wrong from scratch.

What makes it genuinely useful beyond the formulas is the gotchas section, each one a real way to get a wrong number without any error being thrown: OpenFDA returns HTTP 404 for an empty result set rather than a 200 with an empty list, so naive code miscounts; the `.exact` query modifier is mandatory for the reaction field or OpenFDA tokenizes a multi-word reaction term into separate words; small counts (a < 3) make PRR/ROR numerically unstable, which is exactly why the shrinkage-based EBGM and IC025 exist; and OpenFDA itself is a sample of FAERS, not deduplicated the way the official quarterly extracts are, so it's a screening tool whose confirmed signals still need reproducing against the curated data. Every threshold in the workflow is explicitly framed as a triage filter for a human safety scientist's review, never a verdict — disproportionality reflects reporting patterns and notoriety bias, not proven causality.

## Tips & Best Practices

- Always use `patient.drug.openfda.generic_name` instead of the free-text `medicinalproduct` field — otherwise brand-name and generic-name reports of the same drug fragment into separate, undercounted buckets.
- For rare events (small `a`), don't trust PRR/ROR at face value — lean on EBGM/EB05 or IC025 specifically because they're built to handle the small-count instability that makes the simpler ratios unreliable.
- Treat OpenFDA as a screening tool, not the final word — reproduce any signal that will actually drive a decision against the official, deduplicated quarterly FAERS extracts before it goes further.

## Limitations

- Statistical screening only — every method here (PRR, ROR, IC, EBGM) detects disproportionate *reporting*, not a proven adverse drug reaction; confounders like indication, notoriety bias, and reporting-stimulation effects require a safety scientist's review before any signal is acted on.
- OpenFDA's live API is a convenient, unlicensed sample of FAERS — it isn't deduplicated the way official quarterly extracts are, so it's appropriate for rapid screening but not as the system of record for a regulatory submission.
- Doesn't implement Empirical Bayes shrinkage (EBGM/EB05) itself — that step is explicitly handed off to a maintained statistical package (`openEBGM` or `PhViD` in R), since a hand-rolled implementation risks getting the shrinkage prior wrong.
