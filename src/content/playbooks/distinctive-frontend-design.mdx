## What This Does

A design-lead persona for frontend work that names the three visual patterns AI output clusters around by default — and explicitly avoids reproducing them unless your brief actually calls for one. Works in two passes: brainstorm a compact design token system grounded in your subject matter, then critique that plan against the generic defaults before writing any code. Builds to an accessibility and responsiveness floor without you having to ask for it separately.

## The Three AI-Design Defaults This Avoids

Named explicitly so Claude can check its own output against them:

1. Warm cream background (`#F4F1EA`-ish) with a high-contrast serif and a terracotta accent
2. Near-black background with one bright acid-green or vermilion accent
3. Broadsheet layout — hairline rules, zero border-radius, dense newspaper columns

All three are legitimate for *some* briefs. The point isn't banning them — it's that they show up regardless of subject when nothing steers the design elsewhere. Where your brief specifies a direction, it always wins, even if that direction happens to be one of these three.

## The Two-Pass Process

**Pass 1 — brainstorm a token system:** 4–6 named hex colors, two-plus type roles (a restrained display face, a body face, an optional utility face), a layout concept sketched in prose and ASCII wireframes, and one signature element the page will be remembered by.

**Pass 2 — critique before building:** check the plan against what a generic version of the same prompt would produce. Anything that reads as the default gets revised, with the change and reasoning stated explicitly. Only after this pass does code get written.

## Tips & Best Practices

- **Ground it in the actual subject** — the subject's own materials, vernacular, and world are where distinctive choices come from, not abstract design theory
- **Spend boldness in one place** — one signature element, quiet and disciplined everywhere else
- **Numbered markers (01/02/03) need a real sequence to justify them** — don't default to them just because they look organized
- **Copy is design material** — write from the user's side of the screen, active voice, one job per element
- **Quality floor is non-negotiable**: mobile-responsive, visible keyboard focus, `prefers-reduced-motion` respected

## Watch Out For

CSS selector specificity conflicts — a type-based selector like `.section` and an element-based one like `.cta` can silently cancel each other out, most often around section padding and margins.
