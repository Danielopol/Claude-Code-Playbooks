## What This Does

Converts an epic into a testable if/then hypothesis with lightweight validation experiments and 2-4 week success measures. Forces explicit assumptions ("we believe X") and falsifiable outcomes ("we know it's valid if Y"), so you can kill bad bets before full engineering commitment.

Built on Tim Herbig's Lean UX hypothesis format. Pairs with `problem-statement`, `proto-persona`, `jobs-to-be-done`, and `user-story-splitting`.

## The Three-Part Structure

1. **If/Then Hypothesis** — If we [action] for [persona], then we will [outcome]
2. **Tiny Acts of Discovery** — 2-3 lightweight experiments (prototype, concierge, landing page, Wizard of Oz)
3. **Validation Measures** — Within [2-4 weeks] we observe [quantitative + qualitative outcomes]

---

## Experiment Types

- **Prototype + user testing** — Clickable mockup with 5-10 users
- **Concierge test** — Manually deliver feature for 10 users
- **Landing page test** — Describe feature, measure interest/signups
- **Wizard of Oz** — Present as automated, deliver manually
- **A/B test** — Test minimal version against control

---

## Tips & Best Practices

- **"Then we will" must be an outcome, not an output.** "Users will have notifications" is output. "Users will respond 50% faster" is outcome.
- **Falsifiable measures only.** If every result confirms the hypothesis, you didn't test it.
- **2-4 week validation window.** Longer windows mean you've already built the thing.
- **Kill cheerfully.** Invalidated hypotheses are saves, not failures.
- **Don't frame post-commitment as hypothesis.** If the CEO already said yes, you're not testing — you're theater-performing.

---

## Common Pitfalls

- Hypothesis is actually a feature spec ("build a dashboard")
- Skipping experiments and going straight to full build
- Vague success criteria ("users are happy") that can't be falsified
- 6-month validation windows where you've already built the thing
- Treating epics as commitments, then running experiments as theater
