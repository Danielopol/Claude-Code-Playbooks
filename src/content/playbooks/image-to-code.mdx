## What This Does

Forces a strict order of operations on visual frontend work: reference first, deep analysis second, implementation third. Instead of jumping straight to code when asked for a landing page or hero section, Claude establishes a visual source of truth (a screenshot, mockup, or generated reference), extracts the actual design system from it (typography, spacing, color, button states, copy), and only then writes the implementation.

The template also encodes a long list of "AI slop" patterns to avoid: purple gradient heroes, three-equal-card rows, cards-inside-cards nesting, generic pill badges, and fake technical microcopy like "orchestration layer." It ships a variation engine (theme, background character, typography character, hero architecture, section system, signature components, motion language) so Claude commits to one coherent visual direction instead of a mashup of defaults.

This is one of three related "Taste Skill" playbooks. This one is for building new sections or pages from a visual reference. Use [Redesign Existing Projects](/playbooks/redesign-existing-projects) instead when the codebase already exists and needs a design audit rather than a fresh build.

Drop a screenshot, mockup, or Figma export into the folder and ask Claude to build it. For sections without an existing reference, ask Claude to describe the visual direction first (theme, hero architecture, component set) before it writes any code.

## The Core Workflow

1. **Establish the reference** — a screenshot, mockup, or generated image. One image per section, not one compressed board for the whole page.
2. **Deep analysis** — extract exact headline text, type scale, spacing rhythm, button states, color palette, and layout structure before touching code.
3. **Implement to match** — build the frontend to be faithful to the reference, not "inspired by" it. No drifting into generic templates during implementation.

If a section image is unclear, the rule is to get a fresh, cleaner image of just that section rather than cropping a low-detail region out of a larger board. Cropping destroys spacing accuracy and type scale relationships.

---

## Hero Rules

The template is strict about the first screen:

- Headline stays within 1-3 lines. If it's running long, cut words instead of wrapping to a 4th line.
- One focal point. No competing elements fighting for attention.
- No stuffing the hero with pills, fake stats, badges, or decorative micro-labels like "00 orchestration layer."
- Must read clean on a small laptop viewport, not just a 27-inch monitor.

## The Variation Engine

To stop every generated page from looking the same, the template makes Claude commit to one combination before building:

- **Theme:** pristine light, deep dark, bold studio solid, or quiet premium neutral
- **Background character:** grid/dotted field, ambient gradient, cinematic imagery, or tactile texture
- **Typography character:** clean grotesk, expressive display, editorial serif+sans, Swiss rational, and others
- **Hero architecture:** cinematic centered, asymmetric split, floating polaroid scatter, editorial offset, and others
- **Signature components:** exactly 4 chosen from a list of distinct patterns (diagonal masonry, 3D card decks, marquee strips, etc.)
- **Motion language:** exactly 2 chosen cues (staggered float-up, parallax drift, scroll-driven reveals, etc.)

Picking a fixed combination up front is what keeps a multi-section build visually coherent instead of turning into eight sections that each look like a different website.

---

## What It Flags as Slop

- **Layout:** giant unreadable collages, identical repeated card rows, cards-inside-cards-inside-cards, giant rounded wrapper sections around everything
- **Visual:** default purple/blue AI gradients, glowing edges, floating blobs, glassmorphism stacked without reason
- **Typography:** giant heading with a weak tiny subcopy, lazy all-caps everywhere, generic gradient headline tricks
- **Copy:** "unleash," "elevate," "revolutionize," "next-gen," "seamless"; fake brand names like "Acme," "Nexus," "NovaCore"
- **Density:** over-packed sections, card overload, tiny gaps between major sections

## Limitations

- Written around an image-generation-first workflow. Without a way to generate images, treat "generate a reference" as "get a screenshot or mockup from the user" — the analysis and implementation discipline still applies.
- The variation engine's choices (theme, architecture, components) are meant as internal direction-setting, not a menu to show the user unless asked.
- Built for marketing sites, landing pages, and portfolio/product pages. It is not tuned for dense internal dashboards or data-heavy admin UIs.
- Faithful matching only goes as far as the reference allows. Ambiguous details still require judgment calls, the template just orders those calls after real extraction instead of before it.
