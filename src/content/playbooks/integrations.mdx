## What This Does

Gives you a status dashboard of the MCP connectors behind a Claude Code marketing setup: which are connected, which are available but not set up, and which skills each one powers. It's the first thing to run after installing the plugin, and again whenever a skill gives you generic output where you expected real data.

---

## Important: This Is a Plugin Command, Not a Standalone Template

This playbook is the `/dm:integrations` command from the **Digital Marketing Pro** plugin. It works by running `scripts/connector-status.py`, a script that ships with the plugin, against the plugin's connector registry. Dropping the CLAUDE.md into an empty folder gives Claude the instructions but not the script, so the dashboard has nothing to read.

To use it as intended:

1. Install the full plugin from its [source repository](https://github.com/indranilbanerjee/digital-marketing-pro), following the setup steps in its README.
2. Run `/dm:integrations` inside a project where the plugin is active.

If you only want to know what's connected in plain Claude Code, without the plugin, see the next section.

## Checking MCP Status Without the Plugin

Claude Code has this built in, just without the marketing-specific grouping:

- Run `/mcp` inside a Claude Code session to see every configured MCP server, whether it connected, and to sign in to servers that use OAuth.
- Run `claude mcp list` in your terminal for the same list outside a session.
- Look at `.mcp.json` in your project root for servers configured at project level, which is the file the plugin's script reads.

What the plugin adds on top is the mapping from each connector to the plugin skills it powers, a per-category coverage count, and advice on what to connect next.

## Reading the Dashboard

The plugin sorts connectors into two transport types, and the difference decides how much setup each one takes:

| Type | How it connects | Setup effort | Where it works |
|---|---|---|---|
| **HTTP** (remote) | Hosted server, you authorize with OAuth the first time a skill needs it | Low: a browser sign-in | Claude Code and other MCP clients |
| **npx** (local) | Runs on your machine, reads an API key from an environment variable | Higher: create an API key, set the variable | Claude Code only |

That's why the "quick wins" list favors HTTP connectors: you get skill coverage for a sign-in instead of an API-key hunt.

## Options

- **Filter by category**: `crm`, `seo`, `advertising`, `email-marketing`, `social-media`, and others. Useful when you only care about one part of the stack.
- **Show**: `connected`, `available`, or `all` (default).

Example: *"Show available advertising integrations"* lists only ad-platform connectors you haven't set up yet, with what each would unlock.

## When to Run It

- **Right after installing the plugin**, to see your starting coverage.
- **When a skill returns generic advice** instead of numbers from your account. Usually its connector isn't active.
- **Before onboarding a new client** (for agencies), to check the connectors match that client's stack.
