## What This Does

Translates plain English descriptions into optimized SQL queries for your specific database dialect. The assistant writes readable, performant queries using CTEs, proper JOIN types, and dialect-specific syntax. It supports PostgreSQL, Snowflake, BigQuery, Redshift, Databricks, MySQL, SQL Server, DuckDB, and SQLite.

## Quick Start

### Step 1: Download the Template

Click **Download** above to get the `CLAUDE.md` file.

### Step 2: Set Up Your Project

Create a project folder and place the template inside:

```bash
mkdir -p ~/Projects/sql-queries
mv ~/Downloads/CLAUDE.md ~/Projects/sql-queries/
```

Optionally add schema documentation or sample data files to the folder.

### Step 3: Start Working

```bash
cd ~/Projects/sql-queries
claude
```

Say: **"Write a query to count orders by status for the last 30 days"**

## Query Best Practices Applied

Every generated query follows these principles:

- **CTEs for readability** -- One CTE per logical step, with descriptive names like `daily_signups` or `revenue_by_product`
- **Performance-first** -- Filters pushed early, partition keys used, `SELECT *` avoided, appropriate JOIN types
- **Commented logic** -- Non-obvious reasoning explained inline
- **Clean formatting** -- Consistent indentation, meaningful table aliases, one clause per line

---

## Tips

- **Mention your dialect upfront** -- "We use Snowflake" gets you correct syntax immediately without a follow-up question.
- **Include table names if known** -- "Query the `orders` table joined with `customers`" saves a round trip.
- **Specify if parameterized** -- For recurring queries, mention "make it parameterized for date range" to get reusable templates.
- **Ask for performance notes** -- The assistant can highlight partition usage, expected cost, and potential bottlenecks.
