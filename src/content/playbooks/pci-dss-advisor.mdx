## What This Does

Turns Claude Code into a PCI DSS compliance advisor covering v4.0.1 (current) and v4.0. It scopes the cardholder data environment (CDE), selects the right SAQ type (A, A-EP, B, B-IP, C, C-VT, P2PE, D), works through all 12 PCI DSS requirements, addresses network segmentation, penetration testing, tokenisation, and PAN encryption, explains merchant and service-provider levels, covers the v4.0 changes, and prepares teams for QSA assessments, ASV scans, ROC, and AOC.

---

## The Problem

PCI scope is where most teams go wrong: pull too much into the CDE and the burden explodes; scope it wrong and you fail. Choosing the correct SAQ, meeting the 12 requirements, and adapting to the now-mandatory v4.0 changes (including new authentication and testing requirements) is a lot of detail — and a QSA will find the gaps you missed.

## Quick Start

### Step 1: Create Your Workspace

```bash
mkdir -p ~/Documents/PCI-DSS
```

### Step 2: Download the Template

```bash
mv ~/Downloads/CLAUDE.md ~/Documents/PCI-DSS/
```

### Step 3: Add Context (Optional)

Describe how card data flows through your systems, your payment integrations, and your network architecture.

### Step 4: Run Claude Code

```bash
cd ~/Documents/PCI-DSS

```

### Step 5: Start

Say: **"Scope our cardholder data environment and tell me which SAQ applies."**

## Tips

- **Minimize the CDE** — the less card data you store and touch, the simpler compliance gets.
- **Get the SAQ right** — it determines which requirements apply.
- **Treat v4.0 changes as live** — several are now mandatory, not future-dated.
