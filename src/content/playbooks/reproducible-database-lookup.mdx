## What This Does

A cross-domain methodology for turning "look this up" into a genuinely reproducible retrieval: define exactly what's being retrieved and from which identifier space before calling anything, select the authoritative source rather than fanning out across every API that might have an answer, make bounded and rate-limited calls with an explicit total-work ceiling, and return results with enough provenance — endpoints, parameters, access date, identifier conversions, count reconciliation — that another agent or a human could replay the exact same lookup and get the exact same answer.

The methodology treats every external API response as untrusted third-party data (never instructions to follow, never safe to paste raw into a shell command), gives concrete recovery paths for the most common failure mode (a wrong identifier format silently returning nothing), and insists on failing *visibly* rather than *plausibly* — if pagination stops early or counts don't reconcile, that gets reported before any conclusion is drawn from the partial data, not papered over with a confident-sounding summary.

## Tips & Best Practices

- The retrieval contract is the single highest-leverage step — most reproducibility failures trace back to an ambiguous scope that got resolved silently, and differently, on the next run.
- Treat a documented rate limit as a real constraint, not a suggestion. Hitting it repeatedly and retrying blindly usually makes a slow retrieval slower, not faster.
- When a query returns exactly zero results, state that plainly first. Broadening the search is a separate, explicit decision — never a silent fallback.

## Limitations

- A methodology, not a list of live API endpoints — specific base URLs, parameters, and rate limits for any given database change over time and should be confirmed against that source's current documentation.
- Bulk or exhaustive retrieval against a large public database can take real wall-clock time even when done correctly — set that expectation before starting a many-page retrieval.
- Best suited to genuinely public, documented APIs — a source requiring a negotiated data-use agreement or non-API access needs a different process entirely.
