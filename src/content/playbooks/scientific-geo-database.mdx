## What This Does

Teaches Claude Code how to work with the Gene Expression Omnibus (GEO), NCBI's public archive of gene expression and functional genomics studies. With the template loaded, you can hand Claude an accession number from a paper ("GSE12345") or a research question ("breast cancer tamoxifen-resistance studies on Affymetrix arrays") and get back a parsed, annotated expression matrix in pandas, plus the sample metadata you need to define your comparison groups.

The template is a detailed code reference covering GEOparse, Biopython's Entrez E-utilities, direct FTP downloads, differential expression and batch processing. Expand it above to read the full code examples. This page covers how to use it well.

## The Four Accession Types, in Practice

| Prefix | What it is | When you'll use it |
|---|---|---|
| **GSE** | A Series: one study, all its samples | Almost always your starting point; papers cite GSE numbers |
| **GSM** | A single Sample | Checking one sample's metadata or processing notes |
| **GPL** | A Platform: the array or sequencer | Mapping probe IDs to gene symbols for microarray data |
| **GDS** | A curated DataSet | Older studies only; most recent work exists only as a GSE |

## Microarray vs. RNA-seq: Where the Numbers Actually Are

This is the most common source of confusion, and it decides which part of the template you need.

- **Microarray studies** usually have a *series matrix* file with one value per probe per sample. GEOparse loads it straight into a DataFrame, but the rows are probe IDs, not genes. Ask Claude to join against the GPL annotation table to get gene symbols, and to decide how to collapse multiple probes per gene (mean, or the highest-variance probe).
- **RNA-seq studies** often have an empty or minimal series matrix. The counts live in **supplementary files** attached to the series, in whatever format the submitters chose. For many human and mouse studies, GEO also provides NCBI-generated raw count matrices on the series page, which are more consistent across studies than submitter files.

A good first prompt is: *"Inspect GSE12345 and tell me where the expression values are, what units they're in, and whether they look log-transformed, before downloading anything large."*

## Checks Before You Trust a Dataset

- **Is it already log-transformed?** Values mostly between 0 and 16 suggest log2. Values in the thousands suggest raw or linear-scale data. Log-transforming twice silently destroys a differential expression result.
- **Are the sample groups where you think they are?** Group labels sit in free-text fields such as `characteristics_ch1` and `source_name_ch1`, formatted differently in every study. Have Claude print the unique values and confirm the treated/control split with you before running statistics.
- **How big is it?** Supplementary archives for large studies run to gigabytes. Ask for file sizes first.

## Combining Several Studies

The template's batch-processing section loops over a list of GSE IDs. For a meta-analysis that's only the first step:

1. Harmonize identifiers across platforms (probe IDs → gene symbols, or Ensembl IDs for RNA-seq).
2. Keep only genes measured in every study.
3. Treat each study as a batch. Combining raw values from different labs and platforms mostly measures the lab, not the biology. Run differential expression per study and combine effect sizes, or use a batch-correction method and say which one in your methods.

## Cite What You Use

GEO data is free for research use, but cite both the original study for every series you analyze and the GEO database itself. Ask Claude to compile the citation for each GSE from its metadata as part of the pipeline, so the references are ready when you write up.
