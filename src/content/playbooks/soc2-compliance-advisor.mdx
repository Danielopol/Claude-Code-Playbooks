## What This Does

Turns Claude Code into a SOC 2 compliance assistant covering all five Trust Services Criteria — Security/Common Criteria (CC1-CC9), Availability (A1), Confidentiality (C1), Processing Integrity (PI1), and Privacy (P1-P8). It runs gap analysis and readiness assessments, writes policies and procedures, documents controls, prepares audit evidence, and handles vendor-risk questionnaires for both Type 1 and Type 2 reports, at any maturity level.

---

## The Problem

SOC 2 is the report enterprise buyers ask for, but it's a moving target: which criteria to include beyond mandatory Security, Type 1 vs. Type 2, what counts as a control, and how to prove it with evidence over a monitoring period. First-timers waste weeks on the wrong things; the most common gaps — undocumented policies, no risk assessment, missing access reviews, untested incident response — are predictable but easy to overlook.

## Quick Start

### Step 1: Create Your Workspace

```bash
mkdir -p ~/Documents/SOC2
```

### Step 2: Download the Template

```bash
mv ~/Downloads/CLAUDE.md ~/Documents/SOC2/
```

### Step 3: Add Context (Optional)

Add existing policies, a description of your system boundary, and your tooling (SSO, logging, ticketing, etc.).

### Step 4: Run Claude Code

```bash
cd ~/Documents/SOC2
claude
```

### Step 5: Start

Say: **"Run a SOC 2 gap analysis for a Type 2 report covering Security and Availability."**

## Tips

- **Choose Type 1 vs. Type 2 deliberately** — Type 2 needs a monitoring period of evidence.
- **Scope the system boundary first** — it defines everything in the report.
- **Automate evidence** where you can — access reviews and logs are the usual pain points.

---

## Important Disclaimer

This is a compliance support tool, not an audit or attestation. A SOC 2 report must be issued by a licensed CPA firm. Have qualified professionals review outputs before relying on them.
