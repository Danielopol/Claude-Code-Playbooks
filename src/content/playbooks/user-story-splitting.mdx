## What This Does

Walks through 8 splitting patterns in order (workflow → business rules → data → AC complexity → major effort → external deps → DevOps → TADs), stops at the first match, and rewrites each split as a complete Mike Cohn + Gherkin story. Validates against INVEST criteria.

Pairs with `user-story`, `epic-hypothesis`, and `jobs-to-be-done`.

## The 8 Patterns

| # | Pattern | Trigger |
|---|---------|---------|
| 1 | Workflow steps | Sequential user journey |
| 2 | Business rule variations | Different rules per scenario |
| 3 | Data variations | Different data types/inputs |
| 4 | AC complexity | Multiple When/Then pairs (most common) |
| 5 | Major effort | Technical milestones |
| 6 | External dependencies | Multiple APIs / third parties |
| 7 | DevOps steps | Deployment / infrastructure phases |
| 8 | Tiny Acts of Discovery | Experiments to unpack unknowns |

---

## Tips & Best Practices

- **Walk patterns in order.** Stop at the first match — don't shop for the "best" pattern.
- **Pattern 4 catches most cases.** If you see 3+ When/Then pairs, split along them.
- **Each split must deliver user value.** No "front-end story" + "back-end story."
- **Validate INVEST.** Independent, Negotiable, Valuable, Estimable, Small, Testable.
- **TADs are experiments, not stories.** Use them when no pattern applies.

---

## Common Pitfalls

- Horizontal slicing (UI / API / DB as separate stories)
- Over-splitting tiny stories (adds overhead)
- Meaningless "first half / second half" splits
- Creating hard dependencies between splits
- Same "so that" on every split (task decomposition in disguise)
