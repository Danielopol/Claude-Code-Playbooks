## What This Does

Wayfinder charts oversized, foggy efforts as a **shared map** of **decision tickets** on your issue tracker — questions whose resolution is a decision, not a slice of a build to execute. It names a destination first (the spec, decision, or change the effort is finding its way to), fans out breadth-first across the open decisions, and creates tickets only for questions sharp enough to state precisely now, leaving everything else in a deliberately incomplete "fog of war" that graduates one patch at a time as earlier tickets resolve.

The discipline that makes it work: plan, don't do. Each ticket resolves exactly one decision, the map is done when nothing's left to decide, and no session resolves more than one ticket (research tickets excepted) — so scope never quietly balloons into execution and no single sitting tries to hold the whole effort in its head.

## Tips & Best Practices

- The destination line is the single highest-leverage sentence on the whole map — get it right before creating a single ticket, since every later "is this in scope" call traces back to it.
- Keep ticket questions genuinely decision-shaped. "Implement the login form" is a task wearing a ticket's clothes; "Which auth provider do we standardize on?" is a real ticket.
- Use your tracker's native blocking/dependency feature if it has one — it renders the frontier visually, so anyone can see what's takeable without opening the map itself.
- Resist resolving two tickets in one sitting even when the second feels quick. The one-ticket-per-session rule is what keeps each resolution properly scoped, not a formality to skip under time pressure.

## Limitations

- Built for genuinely oversized efforts — a task small enough to finish in one sitting doesn't need a map; skip straight to doing it.
- Without a tracker that supports native child-issues and blocking, the fallback (local markdown files) works but loses the visual frontier a real tracker's UI gives for free.
- The map is only as good as its destination. A vague or drifting destination produces a map that never converges — revisit and sharpen it explicitly if tickets start feeling arbitrary.
