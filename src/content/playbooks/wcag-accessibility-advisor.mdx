## What This Does

Turns Claude Code into a WCAG (Web Content Accessibility Guidelines) advisor covering WCAG 2.0, 2.1, and 2.2. It evaluates success criteria, conformance levels (A/AA/AAA), the four POUR principles, ARIA patterns, colour contrast, keyboard accessibility, screen-reader compatibility, mobile and cognitive accessibility, the new WCAG 2.2 criteria, a WCAG 3.0 preview, accessibility statements, and the mapping of WCAG to laws (EN 301 549, EAA, ADA, Section 508).

---

## The Problem

Accessibility is now legally and commercially required, but teams get stuck between high-level intent ("be accessible") and the concrete work of meeting specific WCAG success criteria. Developers need to know exactly which criterion a component fails, why, and how to fix it — with correct ARIA, contrast, and keyboard behavior — and which conformance level and laws apply.

## Quick Start

### Step 1: Create Your Workspace

```bash
mkdir -p ~/Documents/WCAG
```

### Step 2: Download the Template

```bash
mv ~/Downloads/CLAUDE.md ~/Documents/WCAG/
```

### Step 3: Add Context (Optional)

Add component code, HTML, URLs, or a description of the interface you want evaluated.

### Step 4: Run Claude Code

```bash
cd ~/Documents/WCAG
claude
```

### Step 5: Start

Say: **"Audit this component against WCAG 2.2 AA and tell me how to fix the issues."**

## Tips

- **Work criterion by criterion** — it makes issues testable and fixable.
- **Test keyboard and screen reader** — automated checks miss the hardest issues.
- **Target 2.2 AA** — it's the common bar for current accessibility laws.

---

## Important Disclaimer

This is an accessibility support tool, not a legal determination or formal conformance certification. Have qualified accessibility professionals validate audits and statements before relying on them.
